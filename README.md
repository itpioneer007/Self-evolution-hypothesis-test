# 三角色出题

一个很小的出题工具：**指定方案 → 执行 → 反馈**三个角色商量着出一份题，最后把题目列表显示在页面上。

这是从零重新设计的起点。之前的答题、判分、错题本、学习模型、审计台等全部删除了，现在只做出题这一件事。

## 怎么跑

1. 双击打开 `index.html`（不用装任何东西，也不用起服务）。
2. 点右上角**设置**，填 DeepSeek 的接口地址、模型和密钥，点「测试连通性」确认能用。
3. 选教材、单元、题数，点「开始出题」。
4. 出完后是左右分栏：左侧每一轮一张卡片（第几轮、总分、得分条、通过/未通过），点哪轮右侧就显示那一轮的完整题目。默认选中最后通过的轮次。

角色怎么商讨的不在界面上显示，只看每一轮的结果。不到 85 分的轮次也留在左侧，不会被通过的那轮盖掉，可以直接对照每一版改了什么。

密钥只存在浏览器本地，不进代码、不进题目。换浏览器或清缓存要重新填。

## 三个角色各干什么

| 角色 | 干什么 | 看不到什么 |
|---|---|---|
| **指定方案** | 读这个单元的词表、句型、语音点，定下这轮考哪几个点、什么层次、怎么切入 | 不写题干和选项 |
| **执行** | 拿到一个考点，写出一道选择题：题干、三个选项、答案、解析、每个选项的说明 | 不知道学生是谁、以前错在哪 |
| **反馈** | 拿学生画像、出题方案、执行题目三样，按 10 个维度打 100 分，85 分及格 | 不出题、不写解析；只量尺寸并给建议 |

**打分怎么算**：词汇范围 15、语法匹配 12、情境趣味 8、干扰项质量 12、答案唯一 10、无歧义 8、认知负荷 8、格式规范 7、中英对等 10、方案意图一致 10，合计 100 分。答案不唯一、中英不对等、知识性错误会直接压到 85 分以下；方案严重跑偏（意图一致性低于 5 分）会强制警告方案角色。

**不合格时怎么走**：反馈输出的是「给方案的建议」（`feedback_to_thinker`），不是让执行直接改题。代码把建议退回方案角色，由它修订整套方案后再出下一轮，最多 4 轮；某一轮全部题目通过且总分 ≥85 就停。每一轮都是完整的一套题快照，连同那轮的分数和建议一起留下，界面上点轮次就能逐版对照。

方案角色万一少给了考点，代码会从本单元词表里挑没用过的词补上——说 5 道就出 5 道，不靠模型自觉。

## 现在没有什么

明确说一下边界，免得误会：

- **不答题**：页面只出题目列表，学生点不了选项、没有提交按钮。
- **不给学生打分**：反馈角色打的是「题目质量分」，不是学生分数；学生答得对不对这里完全不管。
- **不记学习记录**：没有错题本、没有掌握概率、没有自适应，也没有下一个学生。
- **不展示过程**：界面上只有每一轮的题目和分数，角色说了什么不显示。评分明细可展开看，但不涉及学生数据。

这些都是后面按需再加的东西，现在刻意不放，避免影响这一步的设计。

## 文件

```
index.html            页面骨架：顶栏（设置）+ 出题区
styles.css            样式：绿色主题，无渐变无 emoji
src/app.js            界面：选教材单元、按轮次左右分栏展示题目
src/core/pipeline.js  编排：方案 → 执行 → 反馈 → 下一轮，每轮存完整快照
src/core/agents.js    三个角色的提示词
src/core/llm.js       调模型，只管发请求拿 JSON
src/data/books.js     教材注册表
src/data/textbook.js  教材内容（词表、句型、语音点）
src/data/curriculum.js 当前单元的切片
tools/smoke-test.js   回归测试
```

数据只来自 `src/data/textbook.js`，模型只通过 `src/core/llm.js` 调用，其余各层不碰对方的内部。

## 验证

```
node tools/smoke-test.js
```

35 条断言，盯的是这条最小链路：角色只有三个、三份提示词约束齐全、十维度合计 100 分、方案少给能补满、反馈建议能退回方案、每一轮都留完整题目快照且内容确实不同、轮次分数与建议保留、最多 4 轮。

## 界面设计技能

项目已装 [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)：全局 CLI `uipro` 2.15.0，技能文件在 `.codebuddy/skills/`（7 个技能，含 `ui-ux-pro-max` 主技能）。**重启 AI 助手后**它会对 UI 类需求自动激活。

手动查设计建议（Windows 用 `python`，不用 `python3`）：

```
python .codebuddy/skills/ui-ux-pro-max/scripts/search.py "education assessment tool desktop" --design-system -p "三角色出题"
python .codebuddy/skills/ui-ux-pro-max/scripts/search.py "focus visible keyboard navigation" --domain ux
```

当前界面已经应用了它给的这些规则：极简瑞士风格（网格 / 留白 / 高对比）、语义化颜色 token、每个控件有可见键盘焦点、徽章不换行截断且含义不只靠颜色、动效统一 200ms 并尊重系统的「减少动态效果」。它推荐的落地页 Hero+CTA 模式不适合工具界面，没有采用。

**配色**取自技能数据里的绿色系（E-commerce / Hyperlocal 那套），主色在推荐的 `#059669` 基础上升一档到 `#047857`——原值对白底只有 3.77:1，达不到正文 4.5:1；调整后 5.48:1，沉稳不刺眼。正文 `#064e3b`（9.2:1）、次文字 `#52665c`（6.15:1）、背景 `#f6faf8` 极浅薄荷、选中态 `#d1fae5`、未通过 `#b42318`（6.57:1）。全部组合都过 4.5:1，查了 `ux-guidelines` 里 Contrast Readability / Color Contrast 两条规则。技能查出来的靛蓝、紫色配色没有采用——不符合本项目的绿色主题。
