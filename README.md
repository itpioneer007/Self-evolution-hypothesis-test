# Self-evolution hypothesis test

最小出题测试工作台。用一个学生、一个单元、五道题、跑两轮，验证「规划 → 生成 → 质检 → 作答 → 错题 → 记忆库 → 组卷与停止」这条链能不能让题**不一样**而且**对学生有用**。

链的上半段是出题（题对不对），下半段是作答（他会不会）。只有上半段的出题器等于考试卷：题出得再合规，也证明不了学生学会了什么。

这是实验用的界面模板，不是产品页面，也不是自动出题器。现在只有骨架，后面才「注入灵魂」。

---

## 怎么跑

**方式一（推荐）**：直接双击 `index.html`。零依赖、零构建、离线可用。

**方式二**：起个静态服务器（浏览器对 `file://` 的 localStorage 策略不同，若发现刷新后数据丢失就用这个）：

```bash
cd Self-evolution-hypothesis-test
python -m http.server 8080
# 打开 http://localhost:8080
```

改完代码跑一遍自检（零依赖，只用 Node）：

```bash
node tools/smoke-test.js
```

数据只写浏览器 localStorage（key `sht-minimal-test-v2`；会自动迁移旧版 `v1` 数据），不上传、不接后端、不调模型。顶栏有「重置」与「导出记录」。

视觉：浅蓝 + 蓝主色，无渐变、无 emoji，字体与卡片放大，一屏内呈现。界面只写数据与动作，不写解释性长句。

## 四个 tab，按流程切分

| Tab | 对应环节 | 布局 |
|---|---|---|
| **01 出题** | 环节 1 / 2 / 3 | 左侧三张智能体卡片（每张标出提示词 / 记忆 / 技能），右侧是当前智能体的工作区。一次只显示一个角色 |
| **02 答题** | 学生侧：作答与判定 | 左侧一张答题卡（题干 / 选项 / 提交 / 提示），提交后就地判定；右侧是本轮 5 个考点的状态栏 |
| **03 错题** | 出题侧回边 | 只列学生答错过的题；每题右侧一栏「出题要点」，把出题手册要求的六项直接摆给执行智能体看 |
| **04 日志** | 环节 4 / 5 | 顶部 5 个 KPI；左侧按轮次排的日志（规划 / 待检 / 通过 / 退回 + 条款号 + 这道题的作答）；右侧打回缘由条形图与已占用角度；底部停止决策 |

界面本身不再嵌大段说明文字：产品页该说的是数据，不是设计理由。规范里的解释留在三份 Markdown 里。

### 界面用词对照

界面用短标签，规范文档保留专业叫法，改代码时别混。

| 界面上写的 | 规范文档里的叫法 | 意思 |
|---|---|---|
| 出题角度 | 格子 | 题型＋场景＋考查层次＋错项类型的组合；换措辞、换选项顺序都不算新题 |
| 排 5 个角度 | 变化轴分配 | 给这一轮排 5 个互不重复的出题角度 |
| 按薄弱点填 | 错因 → 建议格子 | 用错题投影出的前 3 条知识点填计划 |
| 退回 / 条款 | 退回原因码 | 挑错时不合格的那一条编号，下一轮要用 |
| 出题要点 | 单题检查表的输入侧 | 知识点颗粒度、能力、错因、建议角度、再错则、教材依据 |
| 独立验证 | 5 题独立认证 | 换 5 道新题确认他真会了，不是靠提示蒙对 |
| 变体题 | 同格子换答案的探针 | 同考点、换掉题面和**答案**（原答案留作干扰项）再问一遍，看他是不是记住了这道题、还是只记住了上次那个选项 |
| 真会 / 只记住这道题 | 掌握判据 | 原题与变体两枪都独立打中才算真会；只打中原题是记住了这道题 |
| 会了 / 卡住 | SATURATED / STALLED | 两种可以停下的理由，必须写依据 |
| 若再错 | 闭环层 L4 | 他错了，下一轮出什么；答不上来这题就不该出 |

三个角色的名字（课程 / 执行 / 验证智能体）保留原流程图的叫法。界面上把三者呈现为**同一个模型的三套配置**：同一底模，不同提示词、不同记忆、不同技能。

### 01 出题 的三个角色

| 角色 | 环节 | 提示词 | 记忆 | 技能 |
|---|---|---|---|---|
| 课程智能体 | 1 规划 | 命题规划 · 5 题配额 | 上轮角度 · 薄弱画像 | 变化轴 · 配额约束 |
| 执行智能体 | 2 生成 | 单题生成 · 九字段 | 仅本单元词表 | 词表取材 · 干扰项设计 |
| 验证智能体 | 3 质检 | 独立质检 · 23 条二元 | 教材词表 · 学生画像 | 四层判据 · 条款号 |

记忆这一列故意不对称：执行智能体**只给词表**，不看画像也不看上轮出了什么，防止写题时照抄；课程智能体才拿上轮角度和薄弱画像。这个隔离是设计的一部分，不是遗漏。

**自动化边界**：界面只自动做五件事——排不重复的出题角度、记录检查结果、算指标、**从当前单元的静态候选里确定性带出 4 项**（见下一节）、**按变化轴接一道同考点的变体**。候选与变体都由教材数据确定性派生，不是模型生成；**题目内容仍全部由人填写**，不接模型。

### 教材知识库：整册入库，按单元切片

`src/data/textbook.js` 是**人教版（PEP）三年级起点 四年级上册**的整册知识库，2026-11-09 从 [English Anchor 教材目录](https://englishanchor.online/downloads/textbooks/) 提供的公开镜像抓取：

| 项 | 内容 |
|---|---|
| 目录页 | `https://englishanchor.online/downloads/textbooks/` |
| 索引 | `https://media.englishanchor.online/ChinaTextbook-hf/search.json`（2027 本教材的路径清单） |
| 文件 | Hugging Face 数据集 `RainPPR/china-textbook-2021-hf` → `小学/英语/人教版（PEP）（三年级起点）（主编：吴欣）/义务教育教科书·英语（PEP）（三年级起点）四年级上册.pdf` |

入库的是**词表、句型表、语音点、情境域、书上页码**，不含课文原文与图片；音标在原 PDF 里是嵌入字体、抽出来是乱码，因此不收。

6 个教学单元：

| 单元 | 标题 | 页码 | 情境域 | 词 | 句 |
|---|---|---|---|---|---|
| U1 | My classroom | 2–11 | 学校 | 18 | 6 |
| U2 | My schoolbag | 12–21 | 学校 | 16 | 5 |
| U3 | My friends | 22–31 | 学校 | 16 | 5 |
| U4 | My home | 36–45 | 家庭 | 14 | 5 |
| U5 | Dinner's ready | 46–55 | 食物饮料 | 22 | 5 |
| U6 | Meet my family! | 56–65 | 家庭 | 18 | 5 |

Recycle 1 / 2 是 U1–U3、U4–U6 的复现，不单独建词表。

**顶栏的单元下拉就是切这本书**。切单元时，词表、句型表、语音点、情境域、候选知识点、示例错题**一起换**——只换词表而让句型表和情境留在上一单元，超纲判定会漏。当前模板打开是 U1 `My classroom`；换成 U5 时情境域会变成「食物饮料」，候选与错题也跟着变。

### 不知道填什么：按单元的候选知识点

`src/data/knowledgePoints.js` 按单元分组，U1 有 8 条、U2–U6 各 5 条，全部只从该书真实材料推导：本单元词表、句型表、Let's spell 的语音对比，以及示例学生在这本教材上的错因。**没有一条是凭空编的**，也没有出现单元外的词句。

每条分三组：他错过的（带真实作答，供 03 错题页）、同一个点换角度考（第 2 轮用）、本单元其他易错点。同一单元内建议出题角度互不相同，所以第 2 轮不会一开局就撞车。每条带 8 样东西：细到错因的知识点、七类能力、错因分类、为什么这个学生该练、教材依据（带页码）、一句示例问法、建议格子、以及「他错了下一轮出什么」（闭环层 L4）。

用法：

- 课程智能体里展开「候选知识点 · U1 · 8」，点「用这个」→ 一次带出知识点 / 能力 / 出题角度 / 下一轮建议，四项都能改。
- 执行智能体里知识点输入框右边有下拉，按组挑，也可以自己填（只带出知识点 / 能力 / 下一轮建议，不动只读的出题角度）。
- 执行智能体底部两个折叠条给出本单元**词表**与**句型表＋语音点**，这是超纲判定的唯一依据。
- 示例问法只是告诉你「可以怎么问」，**不会自动写进题干**。

这份清单真正的用途是定**以后自动生成器的输出规格**：接模型时让它按这 8 个字段产出候选，人只守 23 条判据。它不是答案库，不参与判分，也不会自己写题。

### 02 答题：一题两枪，才判会不会

题目在 01 出，学生在这里做。答题卡上只有这道题、三个选项、提交与提示；听力题在提交前不显示原文（原文由测试者照 01 朗读），提交后回看。

判错很简单，判「会不会」不简单。一条题答对只说明他做对了**这一道**，不说明他会这个考点。所以每个考点打两枪：

| 情况 | 界面动作 | 这个考点记什么 |
|---|---|---|
| 原题答对 | 换下一个考点 | 会用 |
| 原题答错 | 就地换一道**同考点、换掉答案**的变体再问 | 暂记不会 |
| 变体答对 | 换下一个考点 | 真会 / 换个角度才会（取决于原题是否对过） |
| 变体也答错 | 写进 03 错题，换下一个考点 | 不会 |
| 原题对、变体错 | —— | 只记住这道题 |
| 任何一枪用了提示 | —— | 最高只到「看提示才会」，不算真会 |

**变体和出题的判据是反的**，这点最容易搞混：

- 出题要求「落在不同格子」——5 道题全落在同一格是 diversity collapse。
- 变体要求「同格子、换表面、**换答案**」——考点一模一样，但新答案不能等于原题答案，而且原题答案要留在选项里当干扰项。它不是在出第 6 道题，而是在排掉「他背下了这道题」和「他记住了上次那个选项」这两种解释。

**为什么答案必须换**，看一个具体例子。原题：

```
— Where is the picture?
— It's ___ the wall.        A on（正确）   B in   C under
```

如果变体只是换个句子、答案还是 on：

```
— Where is the picture?
— It's ___ the desk.        A on（正确）   B in   C under
```

学生上一枪怎么选、这一枪照选就赢。他根本没去想 on / in / near 的区别，只要记住「上次那个空填 on」就够了。这种变体探的是**答案惯性**，不是考点。

正确的变体要把答案也翻掉，并且把旧答案留在选项里：

```
— Where is it?
— It's ___ the window.      A in   B on   C near（正确）
```

盲选 on 的学生这次会被判错。他不是答错了一道题，是暴露了「上次对了但没懂」。

四条铁律（`SHT.VARIANT_RULES`，接模型后原样写进提示词）：

| # | 规则 | 违反后的样子 |
|---|---|---|
| 1 | 考点与格子不动 | 换了考点，就不是探针，是第 6 道题 |
| 2 | 答案必须换 | 答案不变，答案惯性就能过关 |
| 3 | 原题答案留在选项里当干扰项 | 选项里找不到旧答案，学生只是「没得选」，探针测不出惯性 |
| 4 | 题干、载体、选项一起换 | 只调整选项顺序，等于没换 |

`buildVariant()` 出口有一道 `auditVariant()`：答案没换、答案不在选项里、题干里出现答案原词（拼写题最容易犯）——任何一条不满足就返回 `null`，当「接不出变体」处理，不硬编。这条校验不看生成方自己怎么说。

变体由 `src/core/practice.js` 的 `buildVariant()` 按题型确定性派生，全部从本单元教材数据取，不编内容：

| 题型 | 变体怎么变 | 换的是什么 |
|---|---|---|
| 听音选义 / 中英匹配 | 换词表里另一个词，干扰项也从词表取 | 词 |
| 拼写补全 / 听写 | 换一个 ≥4 字母的词，错拼按「漏元音 / 交换相邻字母」规则生成 | 词 |
| 字母组合辨音 | 换 `phonics.pairs` 里另一组长短音 | 音 |
| 选词填空 / 句子判断 | 取句型表整句，把另一个位置介词挖空（答案随之翻到 in / near / under） | 空 |
| 对话补全 | 取句型表另一组问答，把应答挖空 | 应答 |
| 看图说词 | 接不出来（口语题要语音证据），直接记错题 | —— |

接不出变体时不硬编：卡片会说明，走「直接写错题」。两类情况会接不出：

- **句型表里没有可换的答案**。U3「My friends」是 `Who is he? — He's tall and strong.` 这类句子，没有位置介词可挖。be 动词也不能用来换答案——`He is` 换成 `He are` 是病句，同一句里正确答案唯一，换答案就错。这类题要出第二枪必须**换主语重写句子**，不是确定性派生能干的，得靠模型生成 + 质检。
- **口语题没有文字答案**。看图说词要语音证据，选项框判不出来。

**写进错题的时机**：只有「变体也错」或「接不出变体」才写。首次作答与变体那枪分别落在 `firstAttemptEvidence` 与 `errorCause` 里，不覆盖首次证据。同一个考点只留一条错题案，后续再错只追加作答记录。

### 03 错题 借鉴了主仓什么

数据形状来自 `D:/vscode/Solingo-main`：

- `WrongQuestion`（`src/types/index.ts:310-351`）— 一条错题只存一次，业务键 `wq:{student}:{unit}:{question}`；后续作答只追加到 `variantAttempts`，首次证据冻结在 `firstAttemptEvidence`
- `ExerciseAttempt`（`src/entities/attempt/types.ts:9-60`）— 用时 / 提示 / 重试 / 证据合格性
- `projectWeaknesses()`（`src/entities/weakness-projection/projectWeaknesses.ts:194-295`）— 按知识点分组、优先级打分、队列状态
- `completeRemediationCertification.ts:5-68` — 「已订正不等于已掌握」：5 题独立认证、无提示无重试、分层分数线 A 90 / B 80 / C 70
- `evidencePolicy.ts:3-8` — 模拟 / 自述 / 未观测的证据不算数

**本模板的补充**（主仓没有的）：主仓错因是 AI 自由文本，不可计算。这里加了一层结构化错因分类，并用 `suggestCell()` 把「错因 → 建议格子」算出来，再回写到 01 出题 的配额表。学生侧回边因此闭合：作答 → 错因 → 薄弱画像 → 规划。

逐条对应见 [`docs/SOURCE-MAP.md`](docs/SOURCE-MAP.md)。

## 为什么是零依赖的静态页面

主仓 `D:/vscode/Solingo-main` 是 Vite 5 + React 18 + TypeScript + Tailwind 3 + Zustand。这个模板刻意**没有**照搬构建链，理由是成本：为了跑五道手工题去装一整套依赖、起五个 companion 服务、配 API Key，与「最小验证」的目的相悖。

保持了与主仓一致的是**数据契约和领域逻辑**，不是构建工具：题型、七类能力、知识点 id、情境域口径对齐 `quizAssessment.ts` / `personalization.ts`；指纹沿用 `questionIdentity.ts` 的 FNV-1a 思路，改成按「变化轴四维」判重。教材数据不再从主仓抄，改为直接取自官方教材 PDF（见上一节），因为主仓 `public/quiz/data.js` 只覆盖个别版本和单元，撑不起「整册出题」。

要并回主仓时，`src/core/` 五个文件都是无 DOM 依赖的纯函数，改成 `.ts` 加导出即可；`src/app.js` 的渲染层换成 React 组件。注意主仓学生数据只能走 `StudentWorkspace` + zustand persist（key `solingo-store-v3`），页面禁止直接访问 localStorage，并回时必须换掉。

## 最小测试怎么跑

1. **01 出题**：课程智能体里核对 5 行计划（或点「排 5 个角度」「按薄弱点填」）；执行智能体里逐题填九字段；验证智能体里逐层过 23 条，挂了哪几条自动进日志。
2. **02 答题**：让学生一题一题做。答错会自动换一道同考点的变体；变体也错就自动写进 03 错题。
3. **03 错题**：核对自动写进来的错题与每题右侧的「出题要点」，点「写入计划」把这道题的出题角度带回 01。
4. **04 日志**：看退回集中在哪几条、哪些角度已经占了、哪几个考点答了两次；勾停止理由并写依据，点「进入第 2 轮」。
5. 第 2 轮会先排除历史角度，保留知识点、清空题面；按新角度重出，再走一遍 02 → 03 → 04。
6. 导出 JSON，对照规范文件里的 `最小测试记录表.md` 写结论。

判定指标：

| 指标 | 合格线 | 不达标说明什么 |
|---|---|---|
| 角度重复（KPI「角度重复」） | ≤ 1/5 | ≥ 3/5 说明变化轴没起作用，问题在环节 1 或记忆库没前置 |
| 退回数量 | 第 2 轮低于第 1 轮 | 不降说明退回条款没被用上 |
| 是否提前结束 | 至少出现一次有依据的提前结束 | 两轮都凑满 5 道，说明停止判据没落地 |

作答侧的判据只有一个：**换掉题面和答案还答对才算会**。真会数不涨、而「只记住这道题」和「不会」在涨，说明这一轮出的题在测记忆不在测掌握，问题回到环节 1 和 2。

停止信号取论文的两个：SATURATED（够了，如同一知识点连续三次全对）与 STALLED（卡住，连续两轮卡同一条）。**必须同时勾信号并写依据才算提前结束**，只勾选不写依据不计入指标。

完整规程见 [`docs/SPEC.md`](docs/SPEC.md)。

## 示例数据说明

`src/data/curriculum.js` 里的 5 道示例题全部用 U1 真实词句，且刻意落在 5 个不同格子（02 答题直接拿它们当题源，答错时每道都能接出变体）；`src/data/wrongCases.js` 里 3 条错题案对齐示例学生的三条近期错因。它们是**模板**，不是标准答案，正式测试要换成真实学生数据。

一处真实约束也保留在界面里：U1 话题域是 Our School，情境维度实际只开放「学校」。硬要换到「家庭」「交通」就会引入单元外词汇，直接变超纲题。这正是规范文件里「格子会撞完」那条风险的实例——理论上有 9 × 10 × 4 × 6 个格子，落到具体单元只剩几十个可用。

## 已知边界

- 5 题 2 轮只够看方向，不能证明效果。要证明至少需要 1 个班、3 个单元、纵向 4 周。
- 八条清单里的「答案唯一」在中文释义题里无法二元判定，必须人看。界面不假装能自动判。
- 停止阈值「连续三次全对」尚未校准；模板里连续答错两轮转 `teacher-help` 是对主仓「两轮补救未过」的简化。
- 变体只覆盖能确定性派生的题型。看图说词（口语，要语音证据）与个别单元接不出空位的选词填空/句子判断会退回「直接记错题」，界面会说明，不硬编。
- 判对错是按字符串比对，不是语法判定。同一答案的多种写法（大小写、句末标点）已归一化，但「说得通但措辞不同」的情况判不了，仍靠人。
- 本模板不接 AI 服务。主仓 `/api/ai/analyze` 的 `trainingQuestions` 可以出 3 道题，但按现有立场，AI 只放在「讲错题」这类容错高的位置。
