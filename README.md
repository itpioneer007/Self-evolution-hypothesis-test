# Solingo 出题工作台

面向小学英语教材的自适应出题工具。三个模型角色按顺序跑：**指定方案**（决定考哪几个点）→ **执行**（把方向落成题）→ **反馈**（独立检查题能不能用）。代码闸负责最终放行，学生作答后判分、进错题本，下一轮按错题重新出题——形成一个能自己往前走的闭环。

零依赖、零构建，双击 `index.html` 即可运行。

---

## 它解决什么问题

常规出题器只解决「题对不对」，证明不了「学生会不会」。这中间缺三样东西：

1. **题往他的方向上走**——目标不是「每轮题目都不一样」，而是练过几天之后，题能明显往这个学生的弱项与强项上靠：弱的地方反复验（深度），没测过的地方也要铺到（广度），难度一级一级往上推。了解一个学生不可能靠五六道题，所以按「广度 + 深度」慢慢收敛，而不是每轮换一批新题就算个性化。
2. **判得动**——模型出的题要能被自动判定通过与否，不能全靠人；
3. **记得住**——这一轮错过的考点，下一轮要能自己找回来。

出题数量是一条硬约束：**设定 5 道，就必须出满 5 道**。规划时多要几条当预留，打回时由预留顶上；真凑不满要明说缺几道，不能悄悄少出。

这个工具把这三件事落成可运行、可复算的代码，用最小规模（一个单元、两轮起）验证链路是否成立，再靠多组、跨天累积看收敛。

## 核心特性

- **三个角色，一个模型**：指定方案 / 执行 / 反馈各自独立的提示词与上下文，互不共享。这里说「角色」不说「智能体」——模型不会自己去做事，没有工具、没有跨调用记忆，每次都是代码拼好上下文、调一次、拿回一段 JSON，记忆由代码在两次调用之间搬运。
- **职责不串味**：生成看不到学生画像（防止不自觉降难度）；验证既看不到画像也看不到出题意图（防止同情放水、防止去确认意图而不是独立判断）；课程不写题、不判对错。
- **代码闸有通过权，模型只有否决权**：八条可复算的硬判据（超纲、答案在选项、选项互异、题干泄题、解析空话、听力音文一致、归属合法、同轮不同格）决定一道题能不能进；模型验证只能挑错、不能放行。
- **格子由代码分配**：模型只提「这一轮考什么」，四维格子（题型 × 场景 × 层次 × 错项类型）由代码分配，防止五道题长成一个样，也保证结果可复算。
- **失败全量留痕**：被退回的题记下阶段、条款号、原因、第几次，原因回灌进下一次生成提示词；被放弃的考点进重试队列，下一轮换个角度补上。
- **跨轮错题回练**：这一轮答错 → 当场进错题本 → 下一轮由模型按「同考点、换题面、换答案」重新出题，而不是当轮补一道代码拼出来的固定变体。
- **答错先提示再重选**：第一次错误被保留为原始证据，系统给出题目提示或划掉一个错误选项，学生原地再选一次；提示后改对只记为「看提示才会」，不会覆盖首答错误。
- **诊断给出「为什么」**：答完立刻做选项级归因——他选的那一项和答案差几个字母、读音是否接近、是不是只差一个词形后缀、另外几项为什么被排掉、花了多少秒，都算得出来；结论按「题目 + 答案」冻结，错题本与下一轮规划只读这一份。
- **一套四上课程真数据**：以 `C端产品内容设计.xlsx` 的「四上 单元内容」为唯一课程源，10 个单元的词表、句型、课文和自然拼读一起入库。

## 快速开始

### 环境

- 浏览器：Chrome / Edge 等现代浏览器
- Node.js **18+**（仅用于跑测试脚本，页面本身不需要）

### 打开

**方式一（推荐）**：直接双击 `index.html`。DeepSeek 接口对 `file://` 返回 `access-control-allow-origin: null`，可以直连。

**方式二**：起静态服务器（个别浏览器对 `file://` 的 localStorage 策略不同，刷新后数据丢失时用这个）：

```bash
python -m http.server 8080
# 打开 http://localhost:8080
```

### 配置模型

点击顶栏右上角 **「设置」**，填入：

| 字段 | 默认值 | 说明 |
|---|---|---|
| 接口地址 | `https://api.deepseek.com` | 兼容 OpenAI `chat/completions` 协议 |
| 模型 | `deepseek-chat` | |
| API Key | 空 | 只存本机 localStorage，不落盘、不进仓库、导出 JSON 会剔除 |

填完直接点「测试连通性」即可，无需先保存。成功会显示模型名与耗时，失败会显示错误类型（`auth` / `timeout` / `rate` 等）。

### 跑一轮

1. 在 01 页勾选「纳入」几个考点，确定这一轮的范围；
2. 点「模型出 N 题」，等待 20–70 秒（题量在工具条上的输入框里改，默认 5）；
3. 切到 02 页作答，每题选一个选项 → 「提交」→「下一步」；
4. 切到 03 页看错题是否写入；
5. 回 01 页点「进入第 2 轮」→「模型出 N 题」，此时上一轮错过的考点会由模型重新出题。

## 界面

只有一个界面，三步：**选画像 → 系统出题 → 答题 → 下一轮**。顶栏只有「设置」（填模型密钥）。

| 步骤 | 界面上是什么 | 背后发生什么 |
|---|---|---|
| 选画像 | 教材 / 单元 / 我的水平（基础·中等·较好） | 决定 `bookId`、`unitId`、`learningLayer`；换单元只重建题目与计划，错题记录保留 |
| 出题 | 等待页显示三个角色正在做什么：挑题 → 写题 → 检查题目 | `pipeline.runRound` 跑完：指定方案排考点 → 执行写题 → 反馈检查 → 落库。配额、失败记录不上面板 |
| 答题 | 题干、选项、提交；判完在题目下方给「这道题考的是」（对错都给），答错另给「错在哪」 | 判分走冻结台账；解析取 `analysis`，逐项说明取 `optionNotes` |
| 本轮结果 | 只说「做完了、答对几题」和下一步按钮 | 表现分、知识点评价、难度提示等统计不上面板，存在 `round.report` 与导出 `report` 里 |

**没有开发视图页签。** 出可怜的失败记录、决策依据、会话统计这类开发要看的东西，全部只在导出 JSON 里；用 `node tools/audit-digest.js 文件名` 读成一份人话摘要，或用 `src/dev/audit.js`（保留但不在页面挂入口）按角色流水复盘。这是为「从零重新设计」留的干净起点。

## 工作原理

### 流水线

```
课程（模型提考点）
  → 代码校验：范围 / 层次上限 / 已退役 / 能力配额 / 考点去重
  → 代码分格（四维，模型不参与）
  → 逐题生成（模型）
  → 代码闸 V1–V8（不过就带原因重出，最多 3 次）
  → 独立验证（模型，只能否决，只能判 15 条）
  → 通过则落库；仍不过则记 GIVE_UP
  → 作答后：判分（四段）→ 诊断（代码归因，必要时模型补一次）
```

### 三个角色，各管一段

| 角色 | 干什么 | 看得到 | 刻意看不到 |
|---|---|---|---|
| **指定方案**（课程） | 决定这一轮考哪几个点、到什么层次、往哪个方向压 | 上次错选与耗时、掌握概率（BKT）、反馈的退回原因、考点台账与已用角度 | 不写题干、不写选项、不判对错 |
| **执行**（生成） | 把方案给的方向落成一道题 | 本单元词表与句型、这一行的考点与角度 | 学情（知道「他弱」就会把题出简单） |
| **反馈**（验证） | 只判这道题本身能不能进这一轮 | 题干、选项、答案、解析、词表 | 学情、出题意图（层次与干扰项类型）、同轮其它题 |

分工上的硬规矩：

- **方案不判对错。** 课程写的 `cause` 只是「我打算用哪种错法做干扰项」——这是设计意图，不是对学生为什么错的判断。错因由代码从作答证据里算（`src/core/diagnose.js`），不另设模型角色。
- **反馈不看意图。** 它要是知道「这题应该用形近干扰项」，就会去确认意图，而不是独立判断选项在这道题里成不成立。

### 判题权限

| 角色 | 权力 | 理由 |
|---|---|---|
| 代码闸 `validateQuestion` | **通过权** | 可复算、可回归。它说不过，一定不过 |
| 模型验证 `ROLES.verify` | **否决权** | 说挂才退回；说通过不算数，仍要过代码闸 |

这个不对称是刻意的：生成方和验证方是同一个模型的两套配置，给验证通过权等于让模型给自己判卷。代价是代码闸的误判会直接吃掉题，因此每条判据的误杀都要能被回归测试复现。

23 条检查项里有 **8 条**验证角色拿不到判定所需的信息（要看同轮其它题、学生画像，或课程声明的层次与干扰项类型），提示词里明确让它不要判，判了也不算数；页面上这些条款也标了原因。以前 23 条一股脑塞过去，它只能编——失败日志里的空话有一部分就是这么来的。

### 错因：不只是「错了」，还要说清「为什么偏选这个」

正确答案是 A，他排掉了 C 和 D 却选了 B。这里要回答的是「为什么偏偏是 B」。答案是代码算出来的，不是模型想出来的，因为同一道题同一个错选，结论必须每次都一样。

| 证据 | 怎么算 | 用来判什么 |
|---|---|---|
| 编辑距离 / 长度比 | 两项逐字比对 | 形近混淆 |
| 音形键 | 常见同音拼法归一后比较 | 音近混淆 |
| 屈折后缀 / 不规则表 | `near → nears`、`have → has` | 语法错形、单复数 |
| 共同前缀 | `class / classroom` | 形近混淆（编辑距离看不出这个） |
| 中文义接近 | 查本单元词表 | 近义混淆 |
| 排除理由 | 另外几项与答案差多远、在不在词表 | 「他不是乱选」的证据 |
| 耗时 / 是否用提示 | 秒选、正常、想了很久 | 给结论打可信度折扣 |

开放题没有选项，就用词元对齐（LCS）看学生写的句子比答案少了、多了、换掉了哪些词：漏 be 动词、漏三单 s、漏冠词、语序按中文排、换成近义词，都能从对齐结果里读出来。

结论按「题目 id + 归一化答案」冻结，与判分台账同一个键：同一个答案重看一百次结论不变，改答案重答是另一条记录。代码没有硬证据时（字母全不一样、对齐不上）就明说证据不足，不另设模型角色去猜一个听上去合理的说法。

### 掌握概率（BKT）

「错过几次」不够用：次数不带顺序，也分不出「错 3 次后连对 2 次」和「连错 3 次」。所以每个考点用贝叶斯知识追踪把作答序列压成一个概率（`src/core/bkt.js`），课程角色读这个数决定下一个考点该压还是该放。用了提示答对会把「蒙对概率」抬高，概率上不去——防止靠提示刷过就算会。

### 解析与诊断的口径

这两件事曾经都被过度解释了，现在收成一条规则：**只有答错才解释，解释必须指向具体证据**。

| 场景 | 以前 | 现在 |
|---|---|---|
| 答对 | 显示一句讲错项的解析；诊断还会按秒数给「像记住了」的结论 | 不显示解析、不做错因归因，只记「对了 / 几秒 / 有没有用提示」 |
| 答错 | 整题只有一句解析，只讲最主要那个错因，另一项一个字没有 | 逐项说明：你选的这项为什么错、正确答案为什么对、另一项为什么错 |
| 题型本身有毛病 | 靠验证角色自己发现「答案不唯一」 | 代码闸加 V9：解析或逐项说明里出现「也可以 / 都成立」，直接判废 |

三条理由：

1. **答对没有可归因的证据。** 错因的证据是错选、排除了哪些项、差几个字母；答对时这些都不存在。按「3 秒内 = 记住了」下结论，等于把「会」判成「背」——而且分不开「本来就会」和「这道题太简单」。
2. **一句解析解释不了三选一。** 学生选错的是 A，解析却在讲 B 为什么不对，等于没回答他的问题。所以生成时要求逐项写（`optionNotes`，每项 ≤14 字，指向具体词与规则），前端按项展示；缺说明的项宁可不显示，也不硬编。
3. **「两个答案都对」最好由代码拦。** 生成方自己写的解析里说「也可以我们来帮你」，这就是它自证两解——这比等验证角色愿不愿意判 C3 可靠。V9 只认明确措辞，否定语境（「不能选它，虽然它也可以」）不误判。

另外验证角色的判据里加了一条：遇到 `let / let's / let me`、`a / an`、`is / are`、`near / nears` 这类同源选项，必须逐项代回题干读一遍，第二项也通顺就判 C3；它说 fail 但给不出条款号时，只要话里是「都成立 / 也可以」，代码按 C3 记成有效否决，不再当弱通过放过。

### 跨轮错题回练

| 步骤 | 发生位置 |
|---|---|
| 答错 → 写进 03 错题 | 02 页「下一步」 |
| 错题进 `priority`，带上考点 id 与上一轮原题题干 | 下一轮 `buildBrief` |
| 命中错题的考点被标记为 `probe` | 流水线（代码标记，不让模型自己声明） |
| 按「同考点、同层次，换场景与问法，换答案」重出 | 生成角色 |
| 回练结果写回错题本，连对两次才算「已掌握」 | 02 页「下一步」 |

一次答对只到「已订正」：可能是蒙对，也可能只是记住了上一轮那道题。

### 答完题之后，下一轮凭什么变

学生端只有一条链：答题 → 记痕迹 → 判分 → 算下一轮 → 再出题。这条链每一环都要有落点，缺一环就会出现「答了白答」——题出了，分判了，下一轮却和上一轮一模一样。

| 学生做了什么 | 记成什么 | 下一轮怎么用 | 在哪 |
|---|---|---|---|
| 选一个选项、改选、把已选的取消 | `pick` / `change` 事件，外加这道题的改选次数 | 改选过再错，不按「手滑」算 | `app.js` 的 `pickOption` + `practice.changes` |
| 提交 | 首答一条 `submit`，提示后一条 `submit` | 两枪都算证据；首答那次错不会被后面的对覆盖 | `submitAnswer` → `learner.evidenceOf` |
| 独立答对 | 这一类权重升，升幅看想了几秒 | 下次同类题出得更难 | `core/weights.js` 的 `update` |
| 答错 | 权重降，同时写进错题本（带**答错当时**的权重快照） | 下一轮优先重出，并降一档 | `writeWrongFromPractice` → `buildBrief.priority` |
| 提示后才答对 | 只算「半会」：权重升一点点（r=0.6），判「掌握不稳」 | 换个角度再验一次，不当作会 | `weights.update` |
| 提示后还是错 | 判「没掌握」，**不判粗心** | 降档重出，不浪费一轮在「换干扰项再验」上 | `learner.tendencyOf`（`retriedWrong`） |
| 答到后半段明显变慢 / 连错 | 判「累了」（`fatigue.level === 'clear'`） | 下一轮降一档，出一组简单的把信心接回来 | `learner.fatigueOf` → `app.js` 的 `planCap` |

三件事要说清楚：

1. **答对也留痕迹，不只是答错。** 权重按对数损失的梯度走：`w ← w + 0.25 × (目标 − 当前)`。答对把权重往 1 推、答错往 0 拉，幅度取决于「意不意外」——预计不会却答对，升得多；预计会却答错，降得多。做题快慢、有没有改选、有没有用提示，都在改这个「目标值」。代码在 `src/core/weights.js` 顶部有完整推导。
2. **权重不是记着好看的，它真的换难度。** 攒够 5 次作答后，`decide()` 收到的 `capOverride` 就是权重算出来的档，这一轮每条题的层次直接跟着它走（`plan.level` → 生成时写进题里）。同一个阶段里，权重最低的考点排在最前面——那是最该验的地方。
3. **难一点是为了挑战，简单一点是为了把人接住。** 三条信号（后半段慢 60% 以上、最近四成题目超过 20 秒、末尾连错两题）命中两条，或者连错三题，就判「累了」，档位降一级。只慢一两题不算——正常思考不该被当成疲劳，否则越练越简单。

### 学生只看题，记录全在后台

学生端只做三件事：选画像、答题、看这一轮的结果。算法跑出来的东西一律不进他的屏幕：

| 只有开发能看到的 | 存在哪 | 长什么样 |
|---|---|---|
| 难度变化台账 | `state.levelTrace` → 导出 `levelTrace` | 每次出题一条：`难度升高 1 级，从第 2 级「辨」（能分清，不容易混）到第 3 级「用」（能自己用对）` |
| 为什么升降 | 同上，`basis` 字段 + `source` | `累计 8 题作答后，预计这类题能答对 68%；超过 60% 的升档线 → 升高 1 级` |
| 为什么降（状态原因） | 同上，`basis.kind = 'fatigue'` | `后半段平均耗时是前半段的 3.1 倍（慢了 210%）；8 题里有 4 题超过 20 秒；最后连错 2 题 → 降低 1 级来照顾状态；只看正确率本该停在第 3 级` |
| 每题的权重变化 | `attempts[].weightAfter / weightDelta` | `weightAfter: 0.56, weightDelta: 0.14` |
| 选题规则与证据 | `state.decisions` → 导出 `decisions` | 规则编号 + 数值 + 原始事件 `seq` |
| 掌握概率、预计答对率、评分公式原文 | 导出 `learner` / `weightsDigest` / 报告 | 界面上一个字都不出现 |

台账的人话翻译在 `src/core/levelTrace.js`，摘要脚本与界面共用同一份，避免两处各说一套。`认 / 辨 / 用 / 表达` 是课程侧的分层名（学习深度），对外一律说成「第 1–4 级 + 这一级意味着什么」——「辨 → 用」这种写法对看的人没有信息量，已经不用了。阈值（升档 60%、降档 35%）跟着记录一起存，算法以后改也解释得清老导出当时按什么算。

`node tools/audit-digest.js audit-xxx.json` 第六段会打印成这样：

```
  1）第 1 组 · 第 1 轮：难度升高 1 级，从第 2 级「辨」（能分清，不容易混）到第 3 级「用」（能自己用对）
     凭什么：累计 8 题作答后，预计这类题能答对 68%；超过 60% 的升档线 → 升高 1 级
     调档依据：累计正确率　（导出 levelTrace 第 1 条）
  2）第 2 组 · 第 1 轮：难度降低 1 级，从第 3 级「用」（能自己用对）到第 2 级「辨」（能分清，不容易混）
     凭什么：最近 8 题里，后半段平均耗时是前半段的 3.1 倍（慢了 210%）；这 8 题里有 4 题超过 20 秒；最后连错 2 题 → 判定为累了或卡住了，所以降低 1 级来照顾状态；只看正确率本该停在第 3 级
     调档依据：作答状态　（导出 levelTrace 第 2 条）
```

每一行都标了它在导出文件里的序号，数字取自那条记录本身，不是脚本二次推断的。

### 练了几天以后，看的是方向，不是“每轮都换题”

目标不是每轮题目都不一样——那只是换题面。要看的是：练过几天，题有没有慢慢往这个学生的方向走，而且覆盖够广、关键处挖得够深。导出里的 `trend` 和 `audit-digest` 第八段给三样东西：

- **方向**：前几轮与后几轮的正确率差。这里不下“自适应有效”的结论——正确率上升也可能是他自己练会的，只能说是观测到的走势。
- **广度**：这个单元覆盖了多少个考点，一共多少个。
- **深度**：多少个考点练过两次以上，平均每个练了几次。只露一次脸的考点不算掌握。

```
答得越来越稳：正确率从 40% 到 80%；广度：覆盖 15/32 个考点；深度：7 个练过两次以上；还有 5 处没掌握
  方向：前段 40% → 后段 80%（+40 个百分点）
  广度：覆盖 15/32 个考点；深度：7 个练过两次以上，平均每个 1.6 次
  难度：共 3 次调整，其中 2 次升高；目前停在第 3 级
```

样本不足两轮时直接写“看不出方向”，不硬造趋势。代码在 `src/core/trend.js`，纯函数，输入是会话记录、难度台账与学习者模型摘要。

**学生端不展示这些统计。** 表现分、四个比例、知识点评价、错题清单、难度升降提示，全部从学生界面撤掉——界面只做题、看每题的解析与错因。「难度为什么变」的判定仍在 `state.levelTrace`，逐行记着从哪档到哪档、谁定的、凭什么；开发视图 07「本轮评价」和 `audit-digest` 第六段照原样呈现，导出 JSON 的 `report` / `levelTrace` 字段也能查。学生唯一会感觉到的是题目本身变难或变简单，不需要读一句解释。

> 早期版本这三处都是断的：改选次数写死在 `app.js` 里恒传 0；权重算出的档位只改了 `state.levelCap` 这个显示值，出题层次仍按旧的掌握概率；提示后重试的那一枪在 `evidenceOf` 里没有对应字段，一段「两枪都算证据」的代码从未被执行过——一题先错后对，被记成「答 1 次、错 0 次」。现在 `tools/smoke-test.js` 的「答题过后重出题」一段专门盯这几种情况。

### 出不成题的两条补救

退三次然后留空，是最省事的做法，也是最差的做法：一轮 5 题实际出 3 题，学生做完就没题了。而三次退回往往卡在同一条上——`V3c`「干扰拼写不像错拼」连着出现三次，说明的不是模型不行，是**这个考点在这个单元里造不出可信的诱饵**。同一个方向再要三次，答案还是同一个。

| 补救 | 什么时候 | 做什么 |
|---|---|---|
| 换相近考点 | 同一格连着 2 次卡在选项 / 干扰项（`V3` `V3b` `V3c`） | 不等第三次，换一个「同能力、字面重合最多」的考点重出，留 `PLAN_SWITCH_KP` |
| 替补顶上 | 次数用满，且换不了 / 已经换过 | 从替补计划里取一条顶这一格，重新分格，留 `BENCH_UP` |

替补不是另开一次模型调用：课程角色这一轮按正取数量的八成多要几条（5 道留 3–8 条），被配额挤出来的、超出总条数的那些就是替补。它们本来就是这一轮想要的方向，顶上去不像外来的题。换考点也不调模型——挑法要能复算（同能力 +2 分，字面重合的词每个 +1 分），而且必须在退题的当下就决定，等一次调用会把「这个考点造不出诱饵」拖成整轮的等待。

替补也用完还不成，就从本单元还没考过的考点补位（`PLAN_POOL_FILL`），保证说 5 道就是 5 道。只有候选也没了才明说少出几道；`GIVE_UP` 的原因会写清「换过相近考点、替补也顶上过」，不再是一句「三次都没过」。

还有一处更早的洞：**模型在规划阶段就可能少给**。实际跑出来过一轮只有 4 题——配额分了 vocab2 / sentence1 / phonics1 / grammar1 共 5 条，模型只回了 4 条计划就 success，而出题循环按「计划有几条」走，于是只有 4 格；上面那些替补和补位都只在已有格子里打转，救不了根本不存在的第 5 格。现在规划提示写明「本轮正取 N 条、一条都不能少」（`src/core/agents.js` 的 plan 角色），代码侧在规划结果进来后先补齐格子再出题（`src/core/pipeline.js` 的 `fillPlanSlots`）：优先补配额里没给够的能力，其次补任意没排过的考点，补进来的格子照样过生成和代码闸。补齐记为 `PLAN_FILL`，导出能看出是补的。

### 句型不会，先看看是不是词不会

一个句子答错，原因常常不在句子结构，而在句子里的某个词。以前系统只看权重：答错过的句型「最该验」，会被排到前面再考一次。结果词没补、句子又错一遍，错还记在句型头上——句型难度越降越低，真正不会的那个词一直没练到。

现在从句型原文里找它用到本单元哪些实词（`a / is / this` 这类功能词不算，`music room` 不会被 `room` 抢走），记成依赖关系。出题时：

- 词还没稳住 → 句型排在词后面，理由写明「句子里的 playground 还没稳住，先补词」；
- 补那个词时 → 理由写明「阶段1句型在等这个词」；
- 词稳住之后 → 句型不再被挡，正常参与排序。

这只调先后顺序，**不减少题量、也不禁止出句型**：词都补完还有空位，句型照出。依赖关系写在课程知识点上（`requires` / `requiresWords`，代码在 `src/data/knowledgePoints.js`），排序与理由在 `src/core/learner.js` 的 `missingPrereqs`；导出 `decisions[].blockedBy` 记着每条选题欠哪个词，`audit-digest` 第六段会打印「这句里的 X 还没稳住，所以排在这些词后面」。

### 中文题干必须是英文答案的忠实翻译

给中文选英文的句子题，题干和答案要逐点对等：答案里有几个人、哪个地点、哪些东西，题干就写几样；答案里没有的，一个字都不许添。否则就会出现题干写「我们学校有一个图书馆」、正确答案却是 `There is a library.` 这种对不上的题——「我们学校」在答案里没有 `in our school` 对应，凭空多了地点。

根因是模型把句型表里的现成例句整句抄来当答案，再倒推一个更长的中文题干；而原来的代码闸只查「答案在不在选项里、超没超纲」，没查中英是否对等。修法是两头立规矩：生成提示第 14 条要求先照答案逐点写题干（附这个错例当反例），验证提示 3.2 条让验证者按 C4「题干自洽」判这类题挂掉。规矩写在 `src/core/agents.js` 的 `generate/verify.system`，条款文本在 `src/core/checklist.js`；`tools/smoke-test.js` 有四条断言盯着这些提示词不被改没。

### 考点推进

每个考点按 **认 → 辨 → 用 → 表达** 升层（对外一律说成第 1–4 级：能认出 / 能分清 / 能自己用对 / 能说出来，见 `src/core/levelTrace.js`）。真会升一层，答错降一层；到顶层且已经会过两次就退役，不再排题。学生分层决定层次上限（A 到表达、B 到用、C 到辨），模型给出的层次超过上限会被代码压回去并留痕。

### 判分

字符串归一化只对「答案唯一、写法固定」的题成立。开放题的答案是一个意思，不是一串字符，比不完。所以判分按代价从低到高走四段，能早停就早停：

| 段 | 判据 | 结果 |
|---|---|---|
| ① 冻结台账 | `(题目, 归一化答案)` 已有记录 | 直接取结论，永不重判 |
| ② 归一化比对 | 去标点、不分大小写后与标准答案相同 | 判完即落库 |
| ③ 可接受答案 | 命中题目预置的 `acceptable`（同义写法） | 判完即落库 |
| ④ 模型判定 | 以上都不中 | 调一次，结果立刻落库冻结 |

选择题在 ② 就结束：选项是封闭集合，答案就在里面，选了别的就是错，不需要问模型。只有开放题会走到 ④。

开放题的来源：题目标 `open:true`、或选项不足两个。看图说词天然是开放题。01 页出题表单里有「作答方式」下拉，可以手动把任一道题改成「自己写」。

**冻结**是这条链的地基。同一题同一答案只判一次，结论写进 `gradeLedger`，错题本、考点推进、统计都读这一条。不冻结的话三者各调一次模型、各拿一个答案，同一份作答在不同面板上显示不同结论，指标就没法信任了。

冻结挡的是「机器自己改口」，不是「人不许改」。模型判错了，判定条上有「判错了，改成对/错」，改判写成 `via:'human'`，原模型判定留在 `modelFirst` 里备查。

模型不可用时会明确报「判分没跑成」，**不默认判错**。服务挂了不是学生的错；一旦记错，错题本和考点推进会把错误一路带下去，而且因为冻结再也纠不回来。

| 判定来源 | 含义 |
|---|---|
| 与标准答案一致 | 规则判的，不可能变 |
| 与可接受答案一致 | 规则判的，命中了同义写法 |
| 模型判定 | 可以人工改判 |
| 人工改判 | 人覆盖了模型，原判留档 |

三条实现取向：

- **摆原料，不摆结论。** 指标卡只能告诉你「3/5 换了答案」，说不出是哪一道、被谁放行。所以每段都把考点原文、题干选项、拦截理由、诊断证据原样贴出来。
- **只判代码真能判的事。** 考点是否一致、逐项说明是否齐全、`parentQid` 指不指得到、答案换没换——这四件是硬事实；「有没有贯彻指定错法」是语义判断，交给人看原文，不做关键词猜测。
- **跟着顶部 R1 / R2 走。** 第 2 轮还没作答时，诊断页会提示「第 1 轮有 2 条答错记录，切到 R1 可以看」，而不是空着。

导出 JSON 给的是当前轮的原料（`plans / questions / failures / attempts / traces`），评审拿去自己复核，不必相信界面上的判定。

## 已知边界

- **5 题 2 轮只够看方向**，不足以证明效果。要证明至少需要 1 个班、3 个单元、纵向 4 周。
- **题量硬约束，但不掩盖失败**：一格连退会依次换相近考点、替补顶上、没考过的考点补位，说 5 道就出 5 道；只有整个单元都造不出题时才明说少几道，不会把 4 道说成 5 道。
- **换考点依赖候选清单**：换相近考点只在「连着两次卡在选项 / 干扰项」时触发；清单没覆盖到的格子走替补或候选补位。
- **替补不另调模型**：替补取自被配额挤出来的、以及超出总条数的那几条计划；模型给得太少时靠本单元没考过的考点补位，不为此多调一次模型。
- **句型依赖按词表匹配**：只认本单元词表里出现过、且不是功能词的那些词。句型用到课外词或换种写法（缩写、时态变化），依赖就识别不出来，仍会当成「句型不会」。
- **「答案唯一」判不了**：代码无法二元判定 `It's ___ the wall` 填 `near` 是否也通顺，只能靠模型验证，三轮改不好就放弃那一格。
- **解析长度与解释深度有张力**：解析超过 30 字判不过、超过 25 字给警告，而逐项罗列每个错项本身就写不下。现在靠软否决（只指向解析的否决不废题，标为待润色）绕过去，不是治本。
- **选择题是死判断，开放题不是**：选项封闭的选择题不调模型；开放题走「归一化 → 可接受答案 → 模型兜底」，写法差太远时仍可能判错，模型判的可以人工改判（写 `via: human`）。
- **诊断会受选项数量限制**：三道选项时，选错意味着只排掉一项，「他为什么排掉其它项」的证据比四选一弱；只有两个选项的题几乎没有排除证据。
- **短词归因是近似的**：`in / on` 这种两三个字母的词，形近、音近、用法混都说得通，代码按「用法（近义）」归，属于约定而不是定理。
- **没有作答时长的老数据置信度偏低**：老记录没有 `durationMs`，节奏这条证据缺失，只能靠字母距离与排除理由。
- **口语题接不出回练**：需要语音证据，选项框判不出来。
- **审计台只认存档里有的东西**：`round.plans`（课程输出快照）是后加的，老存档没有它时，01/02 只能从题上反推知识点，读不到错因意图与理由。想快速看版式可以跑 `node tools/shot-audit.js [pane] [路径] [轮次]`，它喂一份样例存档给同一套渲染函数截图，不碰真实数据。
- **伪变体的判定在 `core/audit.js`，不再出现在界面上**：审计页改成摆原料之后，第二轮的「答案没换」是靠在「05 第二轮复用」里标红显示的，不做百分比打分。
- **旧题不会自动重判**：V9 与新的验证判据只对之后生成的题生效。界面上已经存在的题（包括看起来「两个答案都对」的那种）要重出才会走新规则；它们不会在打开页面时被回头检查。
- **逐项说明依赖生成时输出**：`optionNotes` 是生成角色写的，老题与本地兜底题没有就退回一句解析。缺说明的项宁可不显示，也不补一句编的。
- **答对不归因，所以「他是不是真会」只能靠连对两次**：这是刻意的，代价是要多跑一轮才能确认。
- **拦截演练已从界面移除**：它塞坏题验「拦不拦得住」，本质是一次性自测，不属于流水审计；需要的场景用 `tools/shot-audit.js` 或直接看 03 段的真实拦截记录。
- **导出的 JSON 要看复用，先跑摘要**：`node tools/audit-digest.js audit-xxx.json` 把一份导出压成一页，按「第一轮答错 → 错题本 → 本轮 probe/parentQid」三段核一遍，并明确告诉你这份文件能不能自证。导出内容自本轮起包含 `prevRound` 与 `wrongCases`，老文件没有这两段，脚本会报「无法核对」而不是谎报复用率 0%。导出另含 `events`（原始答题轨迹）、`learner`（模型摘要）、`decisions`（本轮选题单，含规则与证据 seq）、`levelCap`、`questionHistory`。摘要脚本第六段按「水平上限 → 每条决策的数值 → 事件 seq 在文件里能查到几条 → 判据 → 题上有没有挂同一份决策」逐条打印。
- **选题决策由代码算，模型只负责写题**：`core/learner.js` 的 `decide()` 把完整轨迹压成结构化选题单，每条带命中的规则编号、参与计算的数值、原始事件 `seq`；`pipeline.runRound` 用它覆盖计划的层次与干扰项，同一份决策写进 `plan.decision` / `question.decision`。导出的 `decisions` + `events` 可逐条回查，`audit-digest.js` 第六段直接打印证据链。仍存的限制：考点对齐靠 `matchPriority` 三层文本匹配，模型把考点改得太远就挂不上；`buildBrief` 那条错题优先级仍只数错次数，两套路径并存。
- **水平会随表现调档**：起始水平按 A/B/C 给上限（A=表达、B=用、C=辨）。作答 ≥5 次后以跨轮累积的权重定档，不够 5 次才用本轮掌握概率（≥0.65 升一档、≤0.35 降一档）；连对的考点出 `R-SOLID-ADVANCE` 进阶题，不再跳回「认」层。注意 `ST_LEVELS` 的显示标签曾把 A 写成「基础」、C 写成「较好」，与算法语义相反，已修正。
- **一组两轮，默认两组、最多四组**：跑满两组时看错题本——还有没掌握的就允许「再练一组」（按钮直接写「还有 3 处没掌握，再练一组」），全掌握了就给终态「重新开始」。四组是硬上限，不会回到无限出下一轮。跨轮/跨组去重靠 `questionHistory`：历史格子进 `used`、题干+选项+答案全同触发 `V_DUP` 退回重出。历史题只留最近 200 道，超出后仍可能与更早的题撞面。
- **权重跨单元共用，没有按单元隔离**：`state.weights.kp` 拿考点标签当键，换到别的单元后，同名考点（如 `library`）的历史权重会带过来；难度档取的是所有考点的平均，会被其他单元的旧数据稀释。现在单册、单学生使用影响不大，要多册并行就得给权重加单元前缀。
- **疲劳只看最近 8 题，跨天的「累」判不出来**：`fatigueOf` 读的是作答耗时与连错，没有把「昨天练了半小时、今天接着练」这类跨会话状态算进去。判为累也只降一档，连错很多不会一路掉到底——宁可少降，不可把学生按到底。
- **题目本身的难度没进权重模型**：同一道题对不同水平的学生都按同一个「对/错 + 三条修正」更新，没有做题目难度校准（IRT 那套需要多人数据）。所以现在的权重是「这个学生在这类内容上大概多稳」，不是「这道题有多难」。
- **轨迹只在本机**：`state.events` 随存档进 `localStorage`，上限 4000 条，导出才带得出去。没有多学生账号、没有服务端，`studentId` 目前恒为 `S-001`；换机或清缓存会丢。
- **界面只放学生要用的，记录留在导出里**：学生端不显示决策规则编号、会话统计、事件 seq 这类内部口径。`state.sessions`（一次练习的起止时间、起始与结束的档位/上限、每轮题量与对错、复用了几道、画像改了几次、事件序号区间）和 `state.profileLog`（教材/单元/水平的每次变更）只在存档与导出里，`audit-digest.js` 第七段打印。单元名用课本原文 `title`，中文 `titleZh` 留在数据里供检索，不上界面——学生要能对着书上的目录找到同一行。
