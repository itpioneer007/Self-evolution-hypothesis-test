# Solingo 出题工作台

面向小学英语教材的自适应出题与验证工具。同一轮里由模型排考点、逐题出题、独立验证；学生作答后先判对错，再由诊断角色说清「他为什么这么答」，错题连同诊断结论进入错题本，下一轮按这条重新出题——形成一个可以自己往前走的闭环。

零依赖、零构建，双击 `index.html` 即可运行。

---

## 它解决什么问题

常规出题器只解决「题对不对」，证明不了「学生会不会」。这中间缺三样东西：

1. **题不一样**——5 道题不能全是同一考点的同一种问法；
2. **判得动**——模型出的题要能被自动判定通过与否，不能全靠人；
3. **记得住**——这一轮错过的考点，下一轮要能自己找回来。

这个工具把这三件事落成可运行、可复算的代码，并用最小规模（一个单元、两轮）验证链路是否成立。

---

## 核心特性

- **四个角色，一个模型**：课程 / 生成 / 验证 / 诊断各自独立的提示词与上下文，互不共享。这里说「角色」不说「智能体」——模型不会自己去做事，没有工具、没有跨调用记忆，每次都是代码拼好上下文、调一次、拿回一段 JSON，记忆由代码在两次调用之间搬运。
- **职责不串味**：生成看不到学生画像（防止不自觉降难度）；验证既看不到画像也看不到出题意图（防止同情放水、防止去确认意图而不是独立判断）；课程不写题、不判对错；诊断不改判定、不改题。
- **代码闸有通过权，模型只有否决权**：八条可复算的硬判据（超纲、答案在选项、选项互异、题干泄题、解析空话、听力音文一致、归属合法、同轮不同格）决定一道题能不能进；模型验证只能挑错、不能放行。
- **格子由代码分配**：模型只提「这一轮考什么」，四维格子（题型 × 场景 × 层次 × 错项类型）由代码分配，防止五道题长成一个样，也保证结果可复算。
- **失败全量留痕**：被退回的题记下阶段、条款号、原因、第几次，原因回灌进下一次生成提示词；被放弃的考点进重试队列，下一轮换个角度补上。
- **跨轮错题回练**：这一轮答错 → 当场进错题本 → 下一轮由模型按「同考点、换题面、换答案」重新出题，而不是当轮补一道代码拼出来的固定变体。
- **诊断给出「为什么」**：答完立刻做选项级归因——他选的那一项和答案差几个字母、读音是否接近、是不是只差一个词形后缀、另外几项为什么被排掉、花了多少秒，都算得出来；结论按「题目 + 答案」冻结，错题本与下一轮规划只读这一份。
- **三本教材真数据**：人教 PEP、冀教版、湘少版四年级上册，词表、句型、语音点、情境域按单元切片，换册时五样边界一起换。

## 快速开始

### 环境

- 浏览器：Chrome / Edge 等现代浏览器
- Node.js **18+**（仅用于跑测试脚本，页面本身不需要）

### 打开

**方式一（推荐）**：直接双击 `index.html`。DeepSeek 接口对 `file://` 返回 `access-control-allow-origin: null`，可以直连。

**方式二**：起静态服务器（个别浏览器对 `file://` 的 localStorage 策略不同，刷新后数据丢失时用这个）：

```bash
python -m http.server 8080
# 打开 http://localhost:8080
```

### 配置模型

点击顶栏右上角 **「模型」**，填入：

| 字段 | 默认值 | 说明 |
|---|---|---|
| 接口地址 | `https://api.deepseek.com` | 兼容 OpenAI `chat/completions` 协议 |
| 模型 | `deepseek-chat` | |
| API Key | 空 | 只存本机 localStorage，不落盘、不进仓库、导出 JSON 会剔除 |

填完直接点「测试连通性」即可，无需先保存。成功会显示模型名与耗时，失败会显示错误类型（`auth` / `timeout` / `rate` 等）。

### 跑一轮

1. 在 01 页勾选「纳入」几个考点，确定这一轮的范围；
2. 点「模型出 N 题」，等待 20–70 秒（题量在工具条上的输入框里改，默认 5）；
3. 切到 02 页作答，每题选一个选项 → 「提交」→「下一步」；
4. 切到 03 页看错题是否写入；
5. 回 01 页点「进入第 2 轮」→「模型出 N 题」，此时上一轮错过的考点会由模型重新出题。

## 四个页签

| 页签 | 作用 |
|---|---|
| **01 出题** | 四张角色卡片（课程 / 生成 / 验证 / 诊断），一次只显示一个角色。上方是题量输入与配额条（七类能力各出几题，总数跟随题量），中间是计划表，下方是失败记录入口 |
| **02 答题** | 学生侧。题干、选项、提交、提示；答错当场说明会写进错题 |
| **03 错题** | 错题本。每条带原题快照、作答与正确答案、错因、教材依据；可「写入计划」带回 01 |
| **04 日志** | 出题日志（带时间与轮次、按状态着色）、没出成的题（按考点分组、按时间排序）、KPI 与停止决策 |

停止有两个信号：**SATURATED**（本轮考点全部真会且不少于 3 个）、**STALLED**（不少于 2 个考点连续过不了闸）。判出来会自动填进停止条并附依据，依据可改。

## 工作原理

### 流水线

```
课程（模型提考点）
  → 代码校验：范围 / 层次上限 / 已退役 / 能力配额 / 考点去重
  → 代码分格（四维，模型不参与）
  → 逐题生成（模型）
  → 代码闸 V1–V8（不过就带原因重出，最多 3 次）
  → 独立验证（模型，只能否决，只能判 15 条）
  → 通过则落库；仍不过则记 GIVE_UP
  → 作答后：判分（四段）→ 诊断（代码归因，必要时模型补一次）
```

### 四个角色，各管一段

| 角色 | 干什么 | 看得到 | 刻意看不到 |
|---|---|---|---|
| **课程** | 决定这一轮考哪几个点、到什么层次、往哪个方向压 | 诊断结论、上次错选与耗时、掌握概率（BKT）、验证的退回原因、考点台账与已用角度 | 不写题干、不写选项、不判对错 |
| **生成** | 把课程给的方向落成一道题 | 本单元词表与句型、这一行的考点与角度 | 学情（知道「他弱」就会把题出简单） |
| **验证** | 只判这道题本身能不能进这一轮 | 题干、选项、答案、解析、词表 | 学情、出题意图（层次与干扰项类型）、同轮其它题 |
| **诊断** | 解释他为什么选了这个、为什么排掉那些 | 题、作答、代码算出来的证据 | 不改判定、不改题、不参与命题 |

分工上的两条硬规矩：

- **课程不判对错，诊断不声明考点。** 错因只能来自诊断，课程写的 `cause` 只是「我打算用哪种错法做干扰项」——这是设计意图，不是对学生为什么错的判断。以前错题本直接抄这个字段，等于出题者给自己判分：学生再错，错题本还是同一句，下一轮照着同一句出，永远出不来。
- **验证不看意图。** 它要是知道「这题应该用形近干扰项」，就会去确认意图，而不是独立判断选项在这道题里成不成立。

### 判题权限

| 角色 | 权力 | 理由 |
|---|---|---|
| 代码闸 `validateQuestion` | **通过权** | 可复算、可回归。它说不过，一定不过 |
| 模型验证 `ROLES.verify` | **否决权** | 说挂才退回；说通过不算数，仍要过代码闸 |

这个不对称是刻意的：生成方和验证方是同一个模型的两套配置，给验证通过权等于让模型给自己判卷。代价是代码闸的误判会直接吃掉题，因此每条判据的误杀都要能被回归测试复现。

23 条检查项里有 **8 条**验证角色拿不到判定所需的信息（要看同轮其它题、学生画像，或课程声明的层次与干扰项类型），提示词里明确让它不要判，判了也不算数；页面上这些条款也标了原因。以前 23 条一股脑塞过去，它只能编——失败日志里的空话有一部分就是这么来的。

### 诊断：不只是「错了」，还要说清「为什么偏选这个」

正确答案是 A，他排掉了 C 和 D 却选了 B。这里要回答的是「为什么偏偏是 B」。答案是代码算出来的，不是模型想出来的，因为同一道题同一个错选，结论必须每次都一样。

| 证据 | 怎么算 | 用来判什么 |
|---|---|---|
| 编辑距离 / 长度比 | 两项逐字比对 | 形近混淆 |
| 音形键 | 常见同音拼法归一后比较 | 音近混淆 |
| 屈折后缀 / 不规则表 | `near → nears`、`have → has` | 语法错形、单复数 |
| 共同前缀 | `class / classroom` | 形近混淆（编辑距离看不出这个） |
| 中文义接近 | 查本单元词表 | 近义混淆 |
| 排除理由 | 另外几项与答案差多远、在不在词表 | 「他不是乱选」的证据 |
| 耗时 / 是否用提示 | 秒选、正常、想了很久 | 给结论打可信度折扣 |

开放题没有选项，就用词元对齐（LCS）看学生写的句子比答案少了、多了、换掉了哪些词：漏 be 动词、漏三单 s、漏冠词、语序按中文排、换成近义词，都能从对齐结果里读出来。

结论按「题目 id + 归一化答案」冻结，与判分台账同一个键：同一个答案重看一百次结论不变，改答案重答是另一条记录。代码没有硬证据时（字母全不一样、对齐不上），界面上才会出现「证据不足，请诊断角色再看一眼」；模型补的那一份是追加，只有在代码原本置信低于 0.4 时才顶上来当主结论。

### 掌握概率（BKT）

「错过几次」不够用：次数不带顺序，也分不出「错 3 次后连对 2 次」和「连错 3 次」。所以每个考点用贝叶斯知识追踪把作答序列压成一个概率（`src/core/bkt.js`），课程角色读这个数决定下一个考点该压还是该放。用了提示答对会把「蒙对概率」抬高，概率上不去——防止靠提示刷过就算会。

### 跨轮错题回练

| 步骤 | 发生位置 |
|---|---|
| 答错 → 写进 03 错题 | 02 页「下一步」 |
| 错题进 `priority`，带上考点 id 与上一轮原题题干 | 下一轮 `buildBrief` |
| 命中错题的考点被标记为 `probe` | 流水线（代码标记，不让模型自己声明） |
| 按「同考点、同层次，换场景与问法，换答案」重出 | 生成角色 |
| 回练结果写回错题本，连对两次才算「已掌握」 | 02 页「下一步」 |

一次答对只到「已订正」：可能是蒙对，也可能只是记住了上一轮那道题。

### 出不成题的两条补救

退三次然后留空，是最省事的做法，也是最差的做法：一轮 5 题实际出 3 题，学生做完就没题了。而三次退回往往卡在同一条上——`V3c`「干扰拼写不像错拼」连着出现三次，说明的不是模型不行，是**这个考点在这个单元里造不出可信的诱饵**。同一个方向再要三次，答案还是同一个。

| 补救 | 什么时候 | 做什么 |
|---|---|---|
| 换相近考点 | 同一格连着 2 次卡在选项 / 干扰项（`V3` `V3b` `V3c`） | 不等第三次，换一个「同能力、字面重合最多」的考点重出，留 `PLAN_SWITCH_KP` |
| 替补顶上 | 次数用满，且换不了 / 已经换过 | 从替补计划里取一条顶这一格，重新分格，留 `BENCH_UP` |

替补不是另开一次模型调用：课程角色这一轮多要 2 条（`want + 2`），被配额挤出来的、超出总条数的那些就是替补。它们本来就是这一轮想要的方向，顶上去不像外来的题。换考点也不调模型——挑法要能复算（同能力 +2 分，字面重合的词每个 +1 分），而且必须在退题的当下就决定，等一次调用会把「这个考点造不出诱饵」拖成整轮的等待。

两条都用完还不行，才留空；`GIVE_UP` 的原因会写清「换过相近考点、替补也顶上过」，不再是一句「三次都没过」。

### 考点推进

每个考点按 **认 → 辨 → 用 → 表达** 升层。真会升一层，答错降一层；到顶层且已经会过两次就退役，不再排题。学生分层决定层次上限（A 到表达、B 到用、C 到辨），模型给出的层次超过上限会被代码压回去并留痕。

### 判分

字符串归一化只对「答案唯一、写法固定」的题成立。开放题的答案是一个意思，不是一串字符，比不完。所以判分按代价从低到高走四段，能早停就早停：

| 段 | 判据 | 结果 |
|---|---|---|
| ① 冻结台账 | `(题目, 归一化答案)` 已有记录 | 直接取结论，永不重判 |
| ② 归一化比对 | 去标点、不分大小写后与标准答案相同 | 判完即落库 |
| ③ 可接受答案 | 命中题目预置的 `acceptable`（同义写法） | 判完即落库 |
| ④ 模型判定 | 以上都不中 | 调一次，结果立刻落库冻结 |

选择题在 ② 就结束：选项是封闭集合，答案就在里面，选了别的就是错，不需要问模型。只有开放题会走到 ④。

开放题的来源：题目标 `open:true`、或选项不足两个。看图说词天然是开放题。01 页出题表单里有「作答方式」下拉，可以手动把任一道题改成「自己写」。

**冻结**是这条链的地基。同一题同一答案只判一次，结论写进 `gradeLedger`，错题本、考点推进、统计都读这一条。不冻结的话三者各调一次模型、各拿一个答案，同一份作答在不同面板上显示不同结论，指标就没法信任了。

冻结挡的是「机器自己改口」，不是「人不许改」。模型判错了，判定条上有「判错了，改成对/错」，改判写成 `via:'human'`，原模型判定留在 `modelFirst` 里备查。

模型不可用时会明确报「判分没跑成」，**不默认判错**。服务挂了不是学生的错；一旦记错，错题本和考点推进会把错误一路带下去，而且因为冻结再也纠不回来。

| 判定来源 | 含义 |
|---|---|
| 与标准答案一致 | 规则判的，不可能变 |
| 与可接受答案一致 | 规则判的，命中了同义写法 |
| 模型判定 | 可以人工改判 |
| 人工改判 | 人覆盖了模型，原判留档 |

## 教材与数据

三本四年级上册教材，按单元切片。切换教材或单元时，词表、句型表、语音点、情境域、功能词白名单五样一起换。

| 教材 | 单元 | 词条 | 说明 |
|---|---|---|---|
| 人教 PEP 四上 | 6 | 104 | 唯一入库了候选知识点清单（U1 有 8 条） |
| 冀教版 四上 | 4 | 77 | 无语音板块 |
| 湘少版 四上 | 12 | 89 | 书后词表是图片，取词自正文，超纲边界更窄 |

数据来自 [English Anchor 教材目录](https://englishanchor.online/downloads/textbooks/) 提供的公开镜像，用 PyMuPDF 抽取文本层后按单元整理。**没有文本层的扫描版不入库**（沪教版、外研社陈琳版四上经检查为 0 字符，已排除）。音标在原 PDF 里是嵌入字体，抽出来是乱码，因此不收。

```

src/
  app.js                    渲染与事件（唯一有 DOM 依赖的文件）

  core/                     全部无 DOM 依赖，可单独 require
    llm.js                  DeepSeek 调用，12 类错误分类，不抛异常
    agents.js               四个角色（课程 / 生成 / 验证 / 诊断）的 system / user / memory
    validate.js             代码闸 V1–V8（有通过权）
    pipeline.js             课程 → 分格 → 生成 → 闸 → 验证 → 退回
    quota.js                能力配额（画像 / 错题 / 范围 / 本册 / 手工）
    bkt.js                  掌握概率（贝叶斯知识追踪）
    progress.js             层次推进、退役、重试队列、停止判据
    agentMemory.js          四个角色各自的记忆（由代码搬运）
    grade.js                判分四段链路 + 冻结台账
    diagnose.js             诊断：选项级归因、词元对齐、冻结台账
    practice.js             考点判定、错题合并、变体派生（已不在主路径）
    wrongBook.js            错题结构、薄弱点投影、诊断错因与出题意图分栏
tools/
  smoke-test.js             主回归（零依赖）
  e2e-browser.js            浏览器端到端（本地 mock 模型）
  ui-check.js               真实点选界面流程（需 key）
  live-run.js               真模型全链路两轮（需 key）
docs/
  SPEC.md                   最小测试规程
  SOURCE-MAP.md             字段与主仓的逐条对应、历次实跑记录
  PLAN-LLM.md               接入模型的方案与落地对照
```

`src/core/` 下所有文件都是纯函数、无 DOM 依赖，合并回主仓时改成 `.ts` 即可。

| ↘ `diagnoses` | 诊断台账：同一个键 → 为什么这么答。判过一次就冻结，模型补诊只追加 |
| `sht-llm-config-v1` | 接口地址、模型名、API Key |

数据只写当前浏览器，不上传、不接后端。API Key 不进仓库、不进导出的 JSON。顶栏有「重置」与「导出记录」。

## 已知边界

- **5 题 2 轮只够看方向**，不足以证明效果。要证明至少需要 1 个班、3 个单元、纵向 4 周。
- **通过率会抖**：配额每类 1 条时没有冗余，一格失败就少一题。同一批考点有时 4 道全出，有时只出 2 道。现在有两条补救（见下），但救不回配额刚好排满、没有替补可用的情况。
- **考点换不了时只能放弃**：换相近考点依赖候选清单（`SHT.kpsOf` 目前只有 PEP 四上有），且只在「连线两次卡在选项/干扰项那几条」时触发；冀教版、湘少版这类书没有池子，只会走替补。
- **替补不另调模型**：替补取自被配额挤出来的、以及超出总条数的那几条计划，所以模型只给正取数量时替补位是空的。
- **「答案唯一」判不了**：代码无法二元判定 `It's ___ the wall` 填 `near` 是否也通顺，只能靠模型验证，三轮改不好就放弃那一格。
- **解析长度与解释深度有张力**：解析超过 30 字判不过、超过 25 字给警告，而逐项罗列每个错项本身就写不下。现在靠软否决（只指向解析的否决不废题，标为待润色）绕过去，不是治本。
- **选择题是死判断，开放题不是**：选项封闭的选择题不调模型；开放题走「归一化 → 可接受答案 → 模型兜底」，写法差太远时仍可能判错，模型判的可以人工改判（写 `via: human`）。
- **诊断会受选项数量限制**：三道选项时，选错意味着只排掉一项，「他为什么排掉其它项」的证据比四选一弱；只有两个选项的题几乎没有排除证据。
- **短词归因是近似的**：`in / on` 这种两三个字母的词，形近、音近、用法混都说得通，代码按「用法（近义）」归，属于约定而不是定理。
- **没有作答时长的老数据置信度偏低**：老记录没有 `durationMs`，节奏这条证据缺失，只能靠字母距离与排除理由。
- **口语题接不出回练**：需要语音证据，选项框判不出来。
