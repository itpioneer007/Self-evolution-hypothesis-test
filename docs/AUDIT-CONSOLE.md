# 审计台设计说明（05 页签）

> 这一页回答的是「四个角色各自做了什么」，不是「达标没达标」。
> 版式是**左侧纵向导航 + 右侧详情**（抽屉式），风格与 01–04 页签一致（浅色、同一套 CSS 变量）。
> 改这一页之前先读一遍，避免把它又做成指标看板。

## 一、它要回答的五个问题

| 导航 | 要回答的问题 | 数据来源 |
|---|---|---|
| 01 课程给点 | 这一轮考哪几个点、每个点希望用哪种错法做干扰项 | `round.plans`（出题时存的课程输出快照） |
| 02 执行理解 | 这些点被执行角色落成了什么题、有没有走样 | `round.questions` + `round.plans` 对照 |
| 03 验证拦截 | 哪些题被拦下、因为哪一条、被拦的题长什么样 | `failures`（stage=verify / validate / giveup） |
| 04 诊断反应 | 学生答错时诊断先记了什么原始证据、又得出什么结论 | `round.practice.attempts[].diag` |
| 05 第二轮复用 | 第二轮是不是真拿了第一轮的错题做变体、答案换没换 | 两轮 questions 的 `parentQid` + `buildBrief.priority` |
| 06 角色留痕 | 每次模型调用谁说了什么、多久 | `state.traces` |

## 二、为什么必须是「过程」而不是「结论」

第一次做这一页时做成了四张指标卡（答案换没换、隔离泄漏没泄漏…），被否掉了。原因很实际：
指标卡告诉你「3/5 换了答案」，但告诉不了你**哪一道没换、它原本该考什么、被谁放行的**。
审计要能追到具体那一道题、那一次判定，否则评审只能提问「为什么」，页面答不上来。

所以每一段都把**原始材料**摆出来：

- 课程给点：考点原文、错因意图、理由（`whyThisOne`）、从哪来（错题回练 / 换考点 / 替补）
- 执行理解：左给点右产出，题干、选项、答案、逐项说明，逐字可比
- 验证拦截：条款号 + 当时的理由 + **当时的题目原文**（从 `failures.detail` 的 JSON 还原）
- 诊断反应：左边是它最初记下的证据（字母差 / 音形 / 中文义 / 排除了谁），右边才是结论
- 第二轮复用：一条链从「第一轮那道题」指到「第二轮的变体」，标出「考点相同 / 答案换了」

## 三、只判代码真能判的事

界面里有几处「判定」，都限制在硬事实上：

| 判定 | 依据 | 不做什么 |
|---|---|---|
| 考点有没有被换掉 | `plan.kp === question.knowledgePoint` | 不判断「换得对不对」 |
| 逐项说明全不全 | `optionNotes` 非空项数 vs 选项数 | 不判断说明写得对不对 |
| 变体有没有挂上原题 | `question.parentQid` 能指到第一轮的题 | 不猜「像不像同一道题」 |
| 答案换没换 | 两次答案归一化后比 | — |

**刻意不判**：执行角色有没有贯彻课程要的那种错法。这是语义判断，关键词匹配会冤枉人——
逐项说明里写「computer 是计算机」其实就是在做「同类不同物」的干扰，只是没出现这四个字。
判不准就不判，把原文摆给人自己看。

## 四、跟随顶部 R1 / R2

审计页读的是**当前轮**（`state.round`）。第 2 轮还没作答时，04 诊断页会是空的——
这时页面会补一句「第 1 轮有 2 条答错记录，切到顶部 R1 可以看」，而不是干巴巴一句「没有记录」。

## 五、数据从哪来（改代码时别丢这三样）

1. **`round.plans`**：出题成功后把 `res.plans` 存进轮次。只存考点、错因、理由、层次、格子、来源
   （`probe` / `switchedFrom` / `fromBench`），不存提示词。丢了它，01 与 02 就只能从题上反推知识点，
   错因意图与理由全没了。
2. **`failures[].detail`**：自动检查与验证退回时把题目原文写成 JSON 存进去。审计要把题还原出来给人看，
   没有它就只能显示「某题被退回」，没法核对拦得对不对。
3. **`traces`**：每次模型调用一行（角色、结论、耗时、条款、它看到的字段）。06 与导出 JSON 都读它。

## 六、导出 JSON

导航底部「导出 JSON」导出的是**当前轮**的原始材料：`plans / questions / failures / attempts / traces`。
给的是原料，不是结论——评审拿去可以自己复核，不必相信界面上的判定。

## 七、样式落点

- 所有审计样式在 `styles.css` 末尾的 `/* 05 审计台 */` 区块，类名统一 `audit-` 前缀
- 不复用旧的深色作用域（已删除 `src/dev/audit.css`）：这一页和其余四页同一个底色、同一套变量
- 版式：`.audit-layout` 两列（250px 导航 + 内容），≤960px 折成单列
