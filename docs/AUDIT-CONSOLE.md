# 审计台设计说明（05 页签）

> 这份文档是「审计台」的设计决议与实现落点。评审想知道**凭什么说达标/不达标**时看这里；
> 改样式或加指标前先读一遍，避免把已经讨论过的取舍又改回去。

## 一、这个界面给谁用

给**开发者与评审**，不是给学生。学生端是浅色的 01–04 页签，审计台是深色作用域（`.audit-root`），不参与出题与判分。

它只回答一个问题：**这套 MVP 的四条达标线，现在过没过。**
过没过由 `src/core/audit.js` 算，界面只显示。渲染层不判断达标，否则导出 JSON 与界面会各说一套。

## 二、总判四态（优先级从上到下）

| 状态 | 什么时候 | 文案 | 颜色 |
|---|---|---|---|
| 未达标 | 任一项算出 `false` | `未达标 · n/4`；若还没跑全：`已跑 n/4 · f 项未达标` | 红 |
| 还没跑够 | 没有 false，但只算出 1–3 项 | `还没跑够 · n/4` | 黄 |
| 达标 | 四项全算出且全过 | `达标 · 4/4` | 绿 |
| 无数据 | 一项都算不出 | `还没跑够 · 0/4` | 灰 |

**红线不染绿**：未达标时只把总判文字与左竖条染红，四指标迷你徽章各用各的状态色——否则评审会以为是「四项都挂」。

## 四、指标卡：固定三段

```
卡头   [①|序号] [标题]                          [状态徽章]
结论   一句 ≤20 字，必须带分子分母
证据   三行，每行 = 灰标签(76px) + 值(13px，单行省略)
卡底   看证据 ↓ n 行（可点，跳到下面的明细区）
```

三条规矩：
1. **卡高固定 156px**，`display:grid` 四行（22/28/54/18）。不固定的话 2×2 里两张卡会错开，评审读不出对齐关系。
2. **证据固定三行**。第四行会被裁掉；要加信息先砍一条旧的。
3. **状态不只靠颜色**：徽章有文字 + 左竖条，卡片有左缘竖条，表行/时间线行有左缘条。

卡内文案模板（照这个句式写，别自由发挥）：

| 卡 | 结论句 | 证据三行 |
|---|---|---|
| ① 变体质量 | `5 道变体 · 答案换 3/5 · 伪变体 1/5（20%）` | 考点必同 / 拦截演练 / 缺来源 |
| ② 信息隔离 | `3 次验证 · 泄漏 1 次` | 看到字段 / 命中词 / 判据 |
| ③ 进化机制 | `5 道挂了来源 · 焦点 1/3 · 难度没跟上` | 挂上来源 / 焦点考点 / 难度档 |
| ④ 工程可复现 | `3 条复算 · 冲突 0 · 四角色 4/4` | 判分台账 / 结论一致 / 依赖模型 |

## 五、明细区

- **变体对照表**（全宽独立块）：`# / 考点 / 上一轮 / 这一轮 / 原答案 / 新答案 / 答案换 / 考点同 / 伪变体`。
  降档：≥1125 全列；1024 起隐藏两个 id 列；<1024 再隐藏两个答案列（保留判定列，永不横滚）。
  点一行展开两版题干；缺 parent 的行排最前并标红。
- **②③④ 用折叠块**（`<details>`），②默认展开（最容易踩线），③④默认收起。标题右侧带一句计数。
- **时间线**：默认 6 条，可按角色筛选（全部/课程/生成/验证/诊断），「再看 n 条」展开。一行 = 时间 / 角色 / 结论一句话 / 耗时 / 条款号。点一行看返回摘要。

## 六、动作

| 按钮 | 主次 | 行为 | 反馈 |
|---|---|---|---|
| 导出 JSON | 主（青绿描边） | 结论 + 逐条证据 + 台账 + 四角色留痕 | 条内一行「已导出 audit-xxx.json（128 KB）」 |
| 刷新重算 | 次 | 按当前存档重算 | 条内一行「已按当前存档重算」 |
| 跑一次拦截演练 | 危险（红描边） | 塞 2 道坏题（超纲 / 答案不在选项里），先过代码闸再问验证角色 | 执行中进度一句话；结束「2/2 拦住」或「有坏题混进来了」 |

## 七、空态文案（不许写「暂无数据」）

| 情形 | 写什么 |
|---|---|
| 一轮都没跑 | 跑两轮之后这里才有可判的东西：一轮出题 + 作答，再出第二轮 |
| 跑了但没变体 | 第二轮还没出题，或者出的题没挂上第一轮的错题 |
| 没有验证调用 | 这一轮还没跑过验证角色。跑一次出题，它每判一道题都会在这里留一行 |
| 没有判分台账 | 还没判过分，不是没达标 |

## 八、实现落点

| 文件 | 负责什么 | 不许做什么 |
|---|---|---|
| `src/core/audit.js` | 四条线的判定（纯函数，可复算） | 不碰 DOM、不做文案 |
| `src/dev/audit.js` | 渲染 + 导出 + 演练 + 增量收集留痕 | 不自己判达标 |
| `src/dev/audit.css` | 深色作用域样式 | 不写全局 `body`/`*`/`:root` 重置 |
| `src/core/llm.js` | 记录 system/user（内存，截 4000 字）+ 自增 id | 不把原文写进 localStorage |
| `src/app.js` | `collectTraces()` 收留痕、切页签时重绘 | 不重复实现判定 |
| `tools/shot-audit.js` | 样例存档 + 同渲染函数出图 | 不写真实存档 |

## 九、面试/评审可能会问的三件事

1. **为什么「没数据」不算达标？** 因为达标是个主张，得有证据。没跑过就报绿，等于把「还没验」当成「验过了」。
2. **伪变体怎么判？** 把答案与三个选项词挖成占位符、去标点，剩下逐字比，完全相同才判伪。相似度算法在这里没用——同考点题天然相似，分数分不开「换场景」和「换人名」。
3. **四角色留痕为什么不留原文？** 验证上下文里有题目、课程上下文里有学生作答，原文落盘等于又存了一份学情，反而成了新的泄漏面。隔离检查在调用当下做完，只落「命中哪个词、第几个字」。
